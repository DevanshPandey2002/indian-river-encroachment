# I-REIM V0.5 — River corridor integration plan

## Objective

Connect the authoritative CWC/NWDP river-polygon source to the Sentinel-2 historical-water workflow.

The CWC/NWDP dataset describes boundaries of rivers and their floodplains. The project should use it as a spatial reference layer, while Sentinel-2 remains the observation source for historical water occupancy.

## Earth Engine setup

The current Sentinel-2 script still uses the small Prayagraj prototype rectangle so it can run immediately.

After obtaining the CWC/NWDP River Polygon GeoJSON/SHP/KML:

1. Import the file into Google Earth Engine Assets.
2. Create a FeatureCollection asset.
3. Copy the asset ID.
4. In water_extraction.js, replace the prototype studyArea with the imported asset geometry.
5. If the national layer contains multiple rivers, filter the FeatureCollection to the Ganga/relevant reach before taking geometry().
6. Run the diagnostic 2026 monsoon product first.
7. Only then launch the historical exports.

## Why we are separating the layers

CWC/NWDP river/floodplain geometry and Sentinel-2 water observations answer different questions:

- CWC/NWDP: where the mapped river/floodplain spatial reference is.
- Sentinel-2: where water was actually observed through time.
- Historical envelope: where water occupancy repeatedly occurred.
- Future corridor model: where river-related spatial evidence should be evaluated for potential human occupation.

A candidate should never be labelled a confirmed illegal encroachment from satellite intersection alone.

## Next processing chain

CWC/NWDP polygon
→ river reach / analysis corridor
→ Sentinel-2 historical water envelope
→ built-up / road / land-use layers
→ spatial intersections
→ potential encroachment candidates
→ verification evidence

## Data provenance requirement

For every exported product, retain:

- source dataset name
- source provider
- asset ID
- acquisition date range
- cloud-probability threshold
- MNDWI threshold
- persistence threshold
- processing script version
- AOI / river reach identifier
- export date

This metadata will become the evidence record attached to every future candidate.
